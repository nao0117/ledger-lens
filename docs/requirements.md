# 資産ダッシュボード 開発要件定義書

- 作成日: 2026-10-01
- 対象: 個人用（利用者は本人のみ）
- 開発環境: VS Code + Claude

---

## 1. 背景と目的

毎月 Google スプレッドシート「資産管理」を更新して資産を管理している。実際に使っているのは「資産ポートフォリオ」と「年次推移」の2シート。

このスプレッドシートを、スマホでも見やすくリッチな Web 画面で確認できるようにする。

**守るべき条件**

1. **スプレッドシートを更新するだけで Web に反映される**（エクスポートやデプロイなどの手作業なし）
2. **資産データを漏洩させない**
3. **無料で運用する**

---

## 2. 全体構成

```
[毎月] Googleスプレッドシートを更新（今まで通り）

[ブラウザ / スマホ]
  ① GitHub Pages から静的アプリ（HTML/JS）を読み込む ← データは含まない
  ② Googleでログイン（Google Identity Services、トークンはメモリのみ）
  ③ Sheets API で「年次推移」と「銘柄マスタ」を読み取り（読み取り専用）
  ④ ブラウザ内で集計・グラフ描画
```

| 要素 | 採用技術 | 費用 |
|---|---|---|
| ホスティング | GitHub Pages（公開リポジトリ） | 無料 |
| 認証 | Google Identity Services（OAuth 2.0 トークンモデル） | 無料 |
| ファイル選択 | Google Picker API | 無料 |
| データ取得 | Google Sheets API v4 | 無料 |
| データ保存 | 既存の Google スプレッドシート | 無料 |

**設計の基本方針**

- **データはどこにもコピーしない**：資産データは Google スプレッドシートにだけ存在する。リポジトリ、ビルド成果物、ブラウザの保存領域、外部サーバーのどこにも置かない。
- **サーバーを持たない**：バックエンドもデータベースも作らない。
- **権限は最小にする**：利用者が Picker で選んだ1ファイルだけを、読み取り専用で読む。

## 4. 入力データの仕様

### 4.1 「年次推移」シート（メインの入力）

現状の構造は次のとおり。

| 列 | 内容 |
|---|---|
| A | 空 |
| B | 大分類（`全資産` / `現金` / `株式`）。集計行にだけ入っている |
| C | 中分類。現金の内訳（`口座預金` / `貯金`）、または証券会社名（例：`証券会社A` / `証券会社B`）。**証券会社名はグループの先頭行にだけ入っている**ので、下の行に引き継ぐ |
| D | 口座区分（`NISA口座` / `NISAつみたて投資枠` / `NISA成長投資枠` / `特定口座` / `信用`）。`信用` の行の値は評価額ではなく損益（負の値もありうる） |
| E | 銘柄名 |
| F 以降 | 2行目が日付、3行目以降がその日付時点の評価額（円）。米国株も円換算済み |

**パース時の要件**

- **シートの集計行は使わない**：全資産・現金・株式の集計行は SUM 式なので、明細行からアプリ側で計算する。シートの集計値とアプリの計算値が一致するかを検証し、ずれていたら画面に警告を出す。
- **日付が空の列は無視する**：数式だけが先に入っている列（右端の未来の列など）がある。
- **同じ日付の列が複数ある場合**：現状、同じ日付の列が2列ある箇所がある。右側の列を採用し、警告を出す。
- **空セルは「保有していない」として扱う**：評価額の計算では 0 と同じ扱いにする。ただし 0 と入力されたセルとは区別する（5.2 を参照）。
- **値は `valueRenderOption=UNFORMATTED_VALUE` で取得する**：日付はシリアル値として返るので変換する。
- **表記ゆれを正規化する**：前後の空白やタブ（例：`NISA成長投資枠\t`）を除去し、全角・半角を統一する。
- **銘柄の一意キー**：`証券会社 + 口座区分 + 銘柄名`。同じ銘柄でも口座が違えば別の行として扱う。
- **行や列が増えても壊れないようにする**：セル番地を決め打ちせず、ヘッダーとラベルから位置を特定する。

### 4.2 「銘柄マスタ」シート（新規作成。利用者が作る）

資産クラスや地域の分類はシートに含まれていないので、分類用のシートを追加する。

> 銘柄名と分類の一覧は保有状況そのものなので、**リポジトリには絶対に置かない**。必ずスプレッドシート側に持たせる。

| 列 | 内容 | 例 |
|---|---|---|
| A: 銘柄名 | 「年次推移」の E 列と同じ表記 | サンプル投信A |
| B: 資産クラス | `投資信託` / `国内株` / `米国株` / `その他` | 投資信託 |
| C: 地域 | `全世界` / `米国` / `先進国` / `日本` / `インド` / `その他` | 全世界 |
| D: 名寄せ名（任意） | 口座をまたいで同じ銘柄として合算するときの名前。空なら銘柄名を使う | サンプル投信A |

- マスタに載っていない銘柄は「未分類」として表示し、一覧画面で目立たせる。
- **名寄せ名（D 列）**：証券会社によって同じ銘柄の表記が違うとき（愛称の括弧書き、運用会社名の接頭辞、「インデックスファンド」の省略など）、それぞれの表記の行の D 列に同じ名前を入れると、1つの銘柄として合算する（F-13）。
  - 表記が違う銘柄を、アプリが自動で合算することはしない。名前が似ていても別のファンドがあるため（「Slim」の有無、「先進国」と「全世界」、為替ヘッジの有無など）。アプリは表記違いの候補を見つけて確認事項に出すだけにする。
  - 名寄せの対応表は銘柄名を含むので、ブラウザには保存せず、スプレッドシート側（このD 列）にだけ持つ。

### 4.3 「資産ポートフォリオ」シート

アプリでは読まない。このシートの内容は、アプリ側の集計で置き換える。

### 4.4 アプリ内部のデータモデル

```ts
type Holding = {
  id: string;            // `${broker}|${account}|${name}`
  broker: string;        // 証券会社A / 証券会社B / 現金
  account: string;       // NISAつみたて投資枠 など。現金の場合は 口座預金 / 貯金
  name: string;
  assetClass: string;    // 銘柄マスタから。なければ '未分類'
  region: string;
  securityName?: string; // 銘柄マスタの名寄せ名（D 列）。なければ name で合算する
};
type Snapshot = { date: string /* YYYY-MM-DD */; holdingId: string; value: number };
```

## 5. 機能要件

### Phase 1（MVP）

| ID | 機能 | 内容 |
|---|---|---|
| F-01 | ログイン | Google ログイン → Picker で資産管理シートを選ぶ。選んだシートの ID は次回以降も使う（保存方法は 7.2 を参照） |
| F-02 | ダッシュボード | 最新の総資産、前回比（金額・%）、前年同時期比、現金と株式の比率（ドーナツグラフ）、資産クラス別の比率 |
| F-03 | 推移 | 総資産の推移グラフ。内訳の切り替え（資産クラス別 / 証券会社別 / 口座区分別 / 銘柄別）。期間の切り替え（1年 / 3年 / 全期間）。銘柄別は口座をまたいで同じ銘柄をまとめ（F-13）、上位7銘柄と「その他」に分ける。信用の損益は同じ銘柄に含める |
| F-04 | 構成 | ツリーマップ（証券会社 → 口座区分 → 銘柄）。基準日を選べる。「銘柄別」に切り替えると、資産クラス → 銘柄（口座をまたいで同じ銘柄をまとめる）で表示し、選んだ銘柄の口座ごとの内訳を見られる。銘柄別の面積は評価額で、信用の損益は含めない |
| F-05 | 銘柄一覧 | 銘柄ごとの最新評価額、構成比、前回比。並べ替え・絞り込みができる。未分類の銘柄を強調表示する |
| F-06 | 金額マスク | ボタン1つで金額を `¥***,***` のように隠す（人前で開くとき用）。比率とグラフの形は表示したままにする |
| F-07 | 再読み込み | ボタンでシートを読み直す |
| F-08 | 自動ロック | 15分操作がなければデータとトークンを破棄し、ログイン画面に戻る |
| F-09 | ログアウト | トークンを失効させ（`google.accounts.oauth2.revoke`）、メモリ上のデータを破棄する |
| F-13 | 銘柄の合算（名寄せ） | 証券会社・口座区分（NISA / 特定など）が違っても、同じ銘柄は1つにまとめて集計する。銘柄一覧は既定でまとめた表示にし、口座ごとの表示にも切り替えられる。まとめた行を開くと口座ごとの内訳が見える。ホームの「今月の動き」もまとめた単位で表示する。詳しいルールは 5.1 を参照 |

### 5.1 銘柄の合算（F-13）のルール

- **名寄せキー**：銘柄マスタの名寄せ名（D 列）。空なら銘柄名。どちらも表記ゆれを正規化してから比べる（4.1 と同じ正規化）。
- **現金**（口座預金・貯金）は銘柄ではないので合算しない。
- **信用**の行は値が損益なので、同じ銘柄にはまとめるが、**評価額には足さない**。内訳に「信用（損益）」として別に表示する。信用の行しかない銘柄は、従来どおり損益を値として表示する。総資産には従来どおり損益を加算する。
- **前回比**は、合算した評価額どうしで計算する（各口座の % の平均にはしない）。片方の口座で新規に買った場合も、合算した前回の値が 0 でなければ % を出す。
- **構成比**は、合算した評価額 ÷ 総資産。信用の損益を足さないため、全銘柄の構成比を足しても 100% にならないことがある。
- **今月の動き**（ホーム）の金額は、総資産の増減への寄与として、信用の損益の変化も含めた合計にする。
- **絞り込み**（証券会社・口座区分など）は、口座ごとの行に先に適用してから合算する（例：証券会社A で絞ると、証券会社A にある分だけの合計になる）。
- **確認事項**として次を出す。
  - 表記違いの候補：括弧書き・4文字以内の運用会社名の接頭辞・「インデックスファンド」「インデックス」「ファンド」・空白と記号を取り除いて比べ、一致するか、6文字以上で一方が他方に含まれるもの。ただし「Slim」「ヘッジ」「毎月」「年1回」「高配当」「レバレッジ」「クラスA」などの語が片方にだけある場合は候補にしない。
  - 名寄せ名でまとめた銘柄どうしで、資産クラスか地域が違うもの。

### 5.2 保有していない銘柄の扱い

- **基準日のセルが空欄**の銘柄は「保有していない」とみなし、銘柄一覧では既定で表示しない。画面の「保有なしの銘柄も表示」で表示できる（表示設定として保存してよい）。
- **0 と入力されたセル**は保有しているとみなして表示する。信用の損益が 0 のときなど、評価額 0 でも保有している場合があるため。
- 銘柄ごとの表示（F-13）では、いずれかの口座で保有していれば保有中とする。一部の口座だけ空欄（売却）になった銘柄は表示し、売った口座の前回の値も前回比に含める。昔から空欄のままの行は、口座の数に含めない。
- ホームの「今月の動き」は、売却した銘柄の減少も見せるため、この規則の対象外（前回比の寄与として表示する）。
- ホームの「未分類の銘柄」の件数は、保有している銘柄だけを数え、銘柄一覧の表示と合わせる。

## 7. セキュリティ要件

### 7.1 想定する脅威と対策

| # | 脅威 | 影響 | 対策 |
|---|---|---|---|
| T1 | 実データをリポジトリにコミットしてしまう（公開リポジトリ） | 資産情報が全世界に公開される | `.gitignore`、開発はダミーデータのみ、GitHub の Push Protection、コミット前の確認（7.4） |
| T2 | GitHub アカウントの乗っ取り → アプリのコードが改ざんされ、データを外部に送信される | 次に自分がログインしたときにデータを抜かれる | **利用者側の GitHub 2段階認証（最重要）**、main ブランチの保護、CSP による送信先の制限 |
| T3 | XSS や悪意ある依存パッケージによるトークンの窃取 | 有効期限内（約1時間）にシートを読まれる | CSP、依存の最小化とバージョン固定、`dangerouslySetInnerHTML` の禁止 |
| T4 | Google アカウントの乗っ取り | シートを直接見られる（アプリの有無に関係ない） | 利用者側の Google 2段階認証・パスキー |
| T5 | 他のサイトに OAuth クライアントを流用される | 利用者を騙して権限を取られる | 承認済みの JavaScript 生成元を github.io と localhost に限定、OAuth アプリをテスト状態にしてテストユーザーを本人だけにする |
| T6 | 端末の紛失や、のぞき見 | 画面のデータを見られる | 自動ロック（F-08）、金額マスク（F-06）、データを端末に保存しない |
| T7 | 権限が広すぎて、他のファイルまで読まれる | Drive 全体が漏洩する | スコープは `drive.file` だけ（Picker で選んだファイルに限定） |
| T8 | 開発中に AI へ実データを渡してしまう | 意図しない場所にデータが残る | 実データの xlsx を開発フォルダに置かない、ダミーデータで開発する |

### 7.2 実装ルール（必須）

**認証・トークン**

- Google Identity Services のトークンモデル（`initTokenClient`）を使う。リフレッシュトークンは扱わない。
- スコープは `https://www.googleapis.com/auth/drive.file` だけにする。`spreadsheets.readonly` や `drive.readonly` は使わない。
- アクセストークンは React の state やモジュール変数などメモリ上にだけ置く。localStorage、sessionStorage、IndexedDB、Cookie、URL には保存しない。
- ログアウトや自動ロックのときは、トークンを revoke してからメモリを破棄する。

**データの扱い**

- シートから取得したデータは、メモリ上でだけ扱う。ブラウザの保存領域にも Service Worker のキャッシュにも保存しない。PWA 化する場合も、データを取得する通信はキャッシュしない。
- `console.log` でデータやトークンを出力しない。本番ビルドでは console 出力を除去する。
- localStorage に保存してよいのは「選んだスプレッドシートの ID」と「表示設定（マスクの ON/OFF、テーマ、期間）」だけ。

**通信の制限（CSP）**

本番ビルドの `index.html` に `<meta http-equiv="Content-Security-Policy">` を入れる。開発中の Vite は inline スクリプトを使うので、本番ビルドのときだけ挿入する。

以下は初期値。Google のログイン画面や Picker の動作を確認しながら、**必要最小限だけ**緩める。

```
default-src 'self';
script-src 'self' https://accounts.google.com/gsi/client https://apis.google.com;
connect-src 'self' https://sheets.googleapis.com https://www.googleapis.com https://oauth2.googleapis.com;
frame-src https://accounts.google.com https://docs.google.com;
img-src 'self' data: https://*.googleusercontent.com https://*.gstatic.com;
style-src 'self' 'unsafe-inline' https://accounts.google.com;
font-src 'self';
object-src 'none';
base-uri 'self';
form-action 'none';
```

- `connect-src` に Google 以外のドメインを追加してはいけない（T2 と T3 への最後の防衛線になる）。
- 外部 CDN、Google Fonts、アクセス解析、エラー監視 SaaS は使わない。

**コード**

- `dangerouslySetInnerHTML`、`eval`、`new Function` は使わない。
- 銘柄名などシート由来の文字列は、必ず React のテキストとして描画する（エスケープされる）。

**リポジトリと CI**

- `.gitignore` に次を入れる：`*.xlsx`、`*.xls`、`*.csv`、`*.json`（`package*.json`、`tsconfig*.json`、`src/**/fixtures/*.json` は除く）、`.env*`、`data/`、`private/`。
- テスト用のデータは `src/**/fixtures/` に**ダミー値だけ**で作る。金額は乱数、銘柄名は「サンプル投信A」のような架空の名前にする。
- GitHub Actions のアクションは、コミット SHA でバージョンを固定する。
- `npm ci` と lockfile を使い、Dependabot（npm と github-actions）を有効にする。
- OAuth クライアント ID と Picker 用の API キーは、Vite の環境変数（`VITE_*`）で渡す。どちらもブラウザに公開される前提の値だが、`.env.local` はコミットしない。Actions には Variables で渡す。

### 7.3 API キーの制限（Picker 用）

- 使える API を Google Picker API だけに制限する。
- HTTP リファラーを `https://<ユーザー名>.github.io/*` と `http://localhost:5173/*` だけに制限する。

### 7.4 コミット前のチェック

```bash
git status
git diff --cached --stat
# 実データが含まれていないか（例：最新の総資産額の一部で検索）
git diff --cached | grep -n "<自分の総資産額の上4桁など>"
```

可能なら、`husky` を使わずに `.git/hooks/pre-commit` で拡張子のチェックを入れる（依存を増やさないため）。

## 8. ユーザー（本人）がやること

### 8.1 開発を始める前に【必須】

- [ ] **GitHub に2段階認証を設定する**（パスキーが望ましい）。リカバリーコードはパスワードマネージャーに保管する。
- [ ] **Google アカウントに2段階認証を設定する**（パスキーが望ましい）。再設定用の電話番号とメールアドレスを確認する。
- [ ] Google Cloud でプロジェクトを作る（課金の設定は不要）。
  - [ ] 「Google Sheets API」と「Google Picker API」を有効にする。

  - 外部への通信（`fetch` の送信先）

### 8.4 何かおかしいと思ったら（インシデント対応）

1. Google アカウントの「サードパーティ製のアプリとサービス」から、このアプリのアクセスを削除する。
2. Google Cloud で OAuth クライアントを無効化または削除し、API キーも削除する。
3. GitHub Pages を無効にし、最近のコミットを確認する。改ざんされていたら revert する。
4. Google と GitHub のパスワードを変更し、ログイン中のセッションをすべてログアウトさせる。
